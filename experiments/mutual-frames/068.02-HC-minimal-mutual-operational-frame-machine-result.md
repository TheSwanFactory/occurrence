# 068.02 — Minimal mutual Operational-Frame machine: execution and presentation order

Implemented and executed using **topographo 0.6.0**. The primary verdict is
**D — NON-SERIALIZABLE / LAW-CONFLICT BOUNDARY**, with the precise scope below.

Two locally deterministic transition rules do not, by themselves, choose a
unique mutual round when each frame reads the other's changing presentation.
AB, BA and staged-input execution can produce three different retained edge
pairs even with the same initial frames and the same enacted SCE law.
Holding the actual presented inputs fixed removes this dependency.

This is an execution-order/presentation boundary, not an inconsistency in
individual Outcome constitution. It is not a proof that every possible mutual
interface requires a new controller. The implementation makes one minimal
presentation interface explicit and tests it rather than inventing a certified
participant-selection law.

### A.2 Exact types and local wiring

```text
Native(x): canonical nonzero rational ray
Cyclic(r,s): canonical ordered cyclic Event edge

OperationalFrame:
    retained_state: Native | Cyclic
    enacted_transition: founding | sce
```

The presentation interface is an explicit experimental choice:

- A Native frame exposes `x` iff `x` is an Event ray. Otherwise presentation is
  unavailable. It does not generate an arbitrary Event from a general ray.
- A Cyclic frame exposes its second/current participant `s`.
- A Cyclic receiver does not read the peer. Its next step is autonomous.

There is no stored global frame identity or selector. The peer relationship is
the supplied two-port wiring of this experiment. Changing which cyclic slot is
exposed would define another interface, not an equivalent implementation change.

### A.3 Presentation, admissibility, execution, retention

For a Native receiver, presentation comes from the peer interface at the read
specified by the diagnostic policy. The local state `x` belongs to the receiver.
The presented Event `z` belongs to the peer and is consumed as an immutable value.

The Event predicate checks pure octonion legs, equal nonzero leg norms and
orthogonal legs. The seed guard checks each leg of `x` is orthogonal to
`H_z=span(1,a,b,ab)`, and excludes `z*x=0`. No normalization square roots are
required because these are homogeneous conditions.

The receiver's fixed local law then enacts:

```text
founding: Native(x), z -> Native([z*x])
sce, guard false: Native(x), z -> Native([z*x])
sce, guard true:  Native(x), z -> Cyclic([z],[z*x])
cyclic:          Cyclic(r,s)   -> Cyclic(s,[r*s])
```

Every cyclic edge is checked independently using the scaled Theory-065 equation
`(r*s)*r = 2*norm2(r)*s`, with both inputs Event rays. Multiplication order and
parentheses remain explicit.

Zero products yield `undefined_projective`, with no operative post-state.
Missing peer Event presentations yield `presentation_unavailable`, also with no
post-state. These are diagnostic failure results, not new physical states or
certified absorbing dynamics. In a failed serial diagnostic the old frame remains
available to the other attempted action, but the combined round is marked
incomplete and never iterated as a valid trajectory.

### A.4 Scheduling probes

- **AB:** A reads B and commits locally; B then reads the updated A.
- **BA:** reverse serial order, with fresh reads.
- **Staged:** both read the immutable incoming pair, then execute their already
  determined local actions. Both computation orders are tested.

The staged helper is a diagnostic shared-read/commit boundary. It is not a
distributed barrier protocol and does not establish that OT already supplies
one. Once those staged encounter inputs are supplied, execution and disjoint
local commits are neutral with respect to computation order.

### B.3 Scheduling outcomes

Counts below compare ordered frame endpoints and require both serial executions
to complete. Agreement of two failed executions is not counted as successful
mutual closure.

- **Native–Native, each law configuration:** 3,024 pairs complete in both serial
  orders; all 3,024 have different endpoints. Staged execution completes on
  6,720 pairs; none of those staged endpoints equals either complete live serial
  endpoint. Of the remaining serial cases, 3,696 lose peer Event presentation
  after the first step; 336 have annihilating input products.
- **Native–Cyclic, each Native law:** 26,208 pairs complete in both serial
  orders; all differ. Each individual policy completes on 26,880 inputs, but
  the failed-input sets differ. Every complete staged outcome equals the
  Native-first serial outcome, as the cyclic step does not consume the Native
  frame. This family has a serializable staged interpretation, without making
  the two live serial orders equivalent.
- **Cyclic–Cyclic:** all 112,896 pairs complete and agree in all policies. This
  is independent local rotation, not continuing two-way encounter exchange.
- **Rational partner sample:** all 80 inputs under each law complete in both
  serial orders and differ; staged endpoints differ from both serial endpoints.

The law itself is never chosen by the scheduler. The read order changes the
presented participant. That can change the seed predicate, successor type and
therefore subsequent law availability. In the SCE/SCE Native census, 5,376
receiver-slot comparisons have different successful post-state types; another
672 have Cyclic post-states in both orders but different edges. In mixed SCE
cases, the corresponding counts are 12,096 and 672. Complete details, including
status and incidence comparisons, are in the two JSON results.

## C. Minimality and no-hidden-controller audit

- **Retained Native ray:** needed for exact multiplication and the seed guard.
  A classification-only value would not supply these operands.
- **Retained ordered cyclic edge:** needed for completion and the next phase.
  It already contains the active relational state, so no extra relational
  field, branch token, cycle ID or mode bit is added.
- **Local enacted law:** needed because a qualifying seed can have Native or
  Cyclic retention under the two admitted laws. It is explicit configuration,
  fixed across compared policies, not a dynamically selected discriminator.
  The field is not consulted during Cyclic continuation; in the implemented
  reachable cyclic cases it is constant `sce`. A compact encoding could omit
  that constant once the state is Cyclic.
- **Presentation and admissibility:** methods/functions consuming the shown
  local/peer operands; no per-instance presentation buffer is preinstalled.
- **Caches:** bounded pure memoization, removable without changing outcomes.
  They are not relational memory or a history tape.
- **Observer traces, A/B slots and case indices:** entirely outside operative
  state. They record which inputs each decision consumed. They never select a
  presented participant or law.
- **Staged incoming pair:** explicitly retained by the diagnostic helper for
  that one experiment. Its semantic role is visible. A live implementation
  that wanted these rounds would need to say how those two presentations are
  fixed; this audit supplies no hidden clock or epoch to do so.

Every local decision records presentation source, predicate inputs, law source
and exact post-state. No global object resolves a set of admissible Events.
The outer harness does select which *diagnostic schedule* is being tested; it
is deliberately not passed off as a neutral semantic scheduler in the cases
where the outputs differ. Its neutrality is demonstrated only for fixed
presented inputs and the autonomous Cyclic–Cyclic sector.

## D. Mutuality verdict and minimal witness

**D — NON-SERIALIZABLE / LAW-CONFLICT BOUNDARY.** The applicable branch of this
verdict is noncommuting live presentation/execution, not a contradiction between
the certified individual laws.

Use these exact rays in the released 061.11 coordinates:

```text
a = [e1 + e10]
b = [e4 + e15]
c = [e5 - e14]
```

They form one cyclic block: projectively `a*b=c`, `b*c=a`, `c*a=b`; reversing
products changes signs, which projectivization removes. Start with
`A=Native(a), B=Native(b)` and the SCE law fixed in both frames.

- **AB:** A reads `b`, retains `(b,c)`; B reads A's new `c`, retains `(c,a)`.
- **BA:** B reads `a`, retains `(a,c)`; A reads B's new `c`, retains `(c,b)`.
- **Staged:** A retains `(b,c)` and B retains `(a,c)`.

All six local transitions are admissible and all endpoints exist. They differ
as projective ordered-edge pairs, not merely by vector sign. The differences
persist under subsequent autonomous cyclic rotations. Holding the two staged
offers fixed reproduces the staged endpoint in either computation order.

The ordering dependence is a **genuine noncommutative execution effect of the
chosen live-read composition**, caused by different presented inputs. It is
not evidence that the same fixed individual encounter has multiple outcomes,
nor an isolated nonassociativity claim. Snapshot computation is neutral only
after an encounter-read boundary has been supplied.

### D.1 What FIPS does and does not supply

The canonical witness stays in one FIPS block with label `(P,delta)=(3,-1)` in
these coordinates. Its six displayed retained edges have that same unordered
triple. FIPS can reconstruct the third participant from an admissible pair and
classify the resulting incidence; it does not retain which receiver read which
phase. Quotienting to the block would hide a difference that continuation uses.

The execution already needs two participants per Cyclic frame. The third ray
is computed, not retained as a third agent or a shared coordination cell. No
Pasch component, Fano label or global FIPS table is consumed by runtime decisions.
Thus the observed useful relational state is the certified ordered edge.
FIPS supplies completion/classification structure, not a demonstrated
synchronization law or a forced third coordinating object.

### D.2 Why the other primary verdicts are not claimed

The autonomous sector and fixed-input actions have closed local execution, but
do not establish ongoing scheduler-neutral reciprocal feedback, so they do not
warrant whole-system A. Staged mutual entry works, but this does not show an
already-licensed automatic shared-read protocol, so whole-system B would
overstate it. No impossibility argument over all possible local interfaces is
given, so C is not established. The package arithmetic and certified operations
were sufficient to run the experiment, so E is not the primary result.

The smallest unresolved specification choice exposed here is **which peer
presentation belongs to each receiver's encounter**: incoming or freshly
updated. A protocol or physical circumstance could settle it without adding an
ontological controller. This experiment does not choose that protocol on behalf
of Theory or Nature.

The following are reproducible candidates for later analysis, not new proofs
claimed by this execution:

1. A live-presentation commutation criterion distinguishing invariant peer
   presentations from order-sensitive feedback, relative to an explicit wiring.
2. The observed basic Native census: no jointly complete live AB/BA pair has the
   same ordered endpoint, under any of the four fixed local-law configurations.
3. The canonical cyclic-triple witness's extension to general admissible cyclic
   pairs, separating edge phase from unordered FIPS classification.
4. A minimal local presentation/staging protocol, if desired, tested as executable
   semantics before making any claim of necessity or physical enactment.
