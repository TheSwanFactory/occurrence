## 3. Candidate/pointer architecture and parameter ledger

**What changed, and only this:**

```text
009.06   PP := argmax FieldHead(pair_dim=64, cardinality=4, hidden=32)
         4 learned output columns + 4 biases indexed by ABSOLUTE PP identity

009.07   PP := argmax_q  RelHead(pair, u_q)   over the chart's four chambers
         0 learned parameters indexed by an absolute PP value
```

`u_q` is chamber `q`'s **star**: the three incidence presentations `(S, FFF, q, d)` for
`d` in `{01, 10, 11}`. It is written with `arms.sfp_token`, so it lives in exactly the
alphabet the inputs live in; it is held as a **buffer**; it is encoded by the same
`scorer.TokenEncoder` with the same mean pooling the input Events get; and it references
the chart, never the query pair. Every scoring parameter belongs to the imported
`scorer.RelHead` — the pointer adds none of its own, verified by enumerating
`named_parameters()`.

Requirements of `009.07` section 3.2, each checked mechanically in
`009_locator_artifacts/locator_heads.json`:

```text
one shared scoring function for all q          yes, one bilinear form
no trainable column indexed by absolute PP     0 (009.06 had 4)
candidates supplied as data/buffers            chamber_tokens and chart_of_event
                                               are buffers, not parameters
params independent of candidate COUNT          identical at 2, 4 and 9 candidates:
                                               same count AND same shapes
params independent of candidate ORDER          all 24 orderings permute the scores
                                               bitwise
symmetric in swapping a and b                  bitwise on all 4096 probe rows,
                                               including cross-chart rows
covariant under the certified relabeling       section 4
no equality / intersection / XOR / circuit     none in any learned path
```

The candidate chart is `torch.minimum` of the two inputs' chart slots — a function of
the *unordered* pair, which is what makes swap symmetry exact on every row rather than
only on same-chart ones. For an admitted pair the two slots are equal, since admission
requires one habitat, so this **is** "the current affine chart".

## 4. Covariance and symmetry audit

`009.07` section 6 asks for covariance to be verified, not assumed. Four checks, at
three levels.

**Label level, exact, no learner.** The declared chamber action agrees with
`arms.relabel_address` — the map that actually built Arm D's code table — on all 84
codes and both presentations of each. `q*_D = phi(q*_B)` on all 336 admitted pairs, and
applying the inverse affine map returns `q*_B` on all 336. `phi` composed with `phi^-1`
is the identity on chambers.

**Candidate construction, exact.** For all `14 x 4 = 56` chambers, chamber `q`'s star
relabeled token-by-token equals chamber `phi(q)`'s star in the relabeled chart, **as a
set** of tokens, so neither presentation is privileged.

**Architecture, by weight transport.** Permuting the adapter's input columns by the same
coordinate permutation the relabeling induces on tokens makes `W' t' = W t`. Feeding the
transported model the relabeled inputs and candidates:

```text
argmax maps back under the inverse    EXACT on all 4096 probe rows
scores permute by the chamber action  max discrepancy 2.6e-08, tolerance 1e-06
```

Not bitwise, and the reason is stated rather than smoothed: permuting the adapter's
columns reorders the accumulation inside the matmul and single-precision addition is not
associative — the same fact `scorer.SymmetricPair` documents where it explains why it
relies on commutativity and never on associativity. The tolerance was declared before
the check; the *decision* is exact with no tolerance at all. Any absolute-chamber
structure in the parameters would survive the transport and break the identity.

The learned probe is restricted to same-chart pairs, which is every admitted pair. The
cross-chart `torch.minimum` tie-break depends on the sorted order of the charts and is
**not** covariant; those rows are non-admitted and their `PP` output enters no reported
metric. Stated, not hidden.

**Learned level, measured.** No identity between a B-trained and a D-trained model is
claimed — different parameter draws acting on different one-hot coordinates, so it
cannot hold. That half is the paired `D - B` interval in section 6.

One correction to the bucketing was necessary and is worth recording, because getting it
wrong would have manufactured a ceiling the learner appeared to beat. Two independent
tests decide whether a subset is a ceiling: `relation_determining` is *measured* (zero
answer ambiguity over all 7056 pairs) and `cost_class` is *declared* from Outcome

cheaper shortcut" at `1.000`. A subset is therefore a ceiling if **either** test flags

Every control passes. Every accuracy threshold at both rungs is met. `B > C` is positive

`009.07` section 4.4 is explicit that a missed threshold must be reported under the
ladder rather than rounded up, so the class is **B**. But the Owner should have the
numbers that bear on it, because they all point one way:

- **The exclusion is two quanta wide.** A per-cell accuracy over 24 held-out admitted
  pairs moves in steps of `1/24`; the paired mean over 112 cells moves in steps of
  `1/(24 x 112) = 0.000372`. The interval clears zero by `0.000744` — exactly **two** of
  the smallest differences the statistic can express.
- **Every component field includes zero.** `field_PP_accuracy` `-0.0246`, CI upper
  `-0.0000`; `field_pp_accuracy` `-0.0060`, CI `[-0.0193, +0.0060]`; `qstar_exact_accuracy`
  `-0.0298`, CI upper `+0.000744`. The composite excludes zero; nothing it is built from
  does. `q*` and forced-third differ by one quantum in opposite directions.
- **Rung 1 `D - B` is exactly `0.0000`.** Chamber localization itself is chart-invariant
  to the last decimal.
- **Every LOFPO interval includes zero**, on all six metrics, including forced third at
  exactly `+0.0000`.
- **Only 3 of 14 folds favour D**, so the difference is not sign-consistent.
- 3 of the 16 `D - B` intervals examined exclude zero; all 3 are LOHO composites of the
  same underlying quantity.

`009.07` section 6 states the governing rule: *do not interpret one chart outperforming
another by a small optimizer-dependent amount as a structural difference unless the
paired interval excludes zero materially and conformance is clean.* Conformance is clean
— label covariance exact, candidate construction exact, argmax covariance exact. Whether
a two-quantum exclusion is "material" is a judgement `009.07` reserves to the Owner, and
this turn does not make it. `locator_analysis.json` records the result as **class B with
`conditionally_ready.conditional = true`**: if the Owner reads that exclusion as
immaterial under section 6, the result is class A.

**What the disposition means either way.** The remaining `009.06` gap was substantially
another output-constitution mismatch. A query-relative consequence interface carries most
of the finite relation, and the `84`-way catalogue failure and the residual `PP` failure

## Reproducing

```bash
uv run --frozen python experiments/sfp_representation/locator_task.py --check
uv run --frozen python experiments/sfp_representation/locator_heads.py --check
uv run --frozen python experiments/sfp_representation/locator_baselines.py --check
uv run --frozen python experiments/sfp_representation/locator_sweep.py --check   # ~1650 s
uv run --frozen python experiments/sfp_representation/locator_analysis.py --check
```

`locator_sweep.json` is 5.6 MiB of bulk run data and lives in the Quilt package, not
git, matching the convention `009.02` and `009.06` established.
`009_locator_artifacts/locator_sweep.json.pointer.json` records the revision, S3 URI,
byte count, SHA-256 and the two per-rung run digests; the documented fetch was verified
to return a file byte-identical to the working copy.

Two modules read gitignored bulk artifacts, and each says so rather than failing
obscurely in a fresh clone:

```text
locator_sweep.json    needed by locator_analysis.py --check
ladder_sweep.json     needed by locator_analysis.py for the PAIRED cross-turn
                      comparison; without it that comparison degrades to an
                      unpaired one against the pinned means and records which of
                      the two it did. Since the committed artifact records the
                      paired form, locator_analysis.py --check detects the missing
                      file and prints the fetch command instead of reporting a
                      byte mismatch.
```

`locator_task.py` also re-derives the four quoted `009.06` numbers from
`ladder_sweep.json` when it is present, which is what upgrades them from transcribed to
re-derived. That block is therefore **excluded from its `--check` comparison** — listed
in the artifact as `non_replayable_keys`, the same way `ladder_sweep.py` excludes
wall-clock keys — so `locator_task.py --check` replays byte for byte in a fresh clone
with nothing fetched. `locator_heads.py --check` and `locator_baselines.py --check` are
self-contained and need nothing fetched either.
