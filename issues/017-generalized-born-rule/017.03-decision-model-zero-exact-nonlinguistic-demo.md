# 017.03 — Build Decision Model Zero, the exact nonlinguistic demonstration

- **Sequence:** 3 of 5
- **Target:** successor Decision Model package work
- **Depends on:** the generic contract completed in 017.02
- **Status:** ready for dispatch
- **Issue effect:** successor work; not an Issue 017 acceptance criterion

## Objective

Ship the smallest installed executable that demonstrates Decision Model's
computational identity without hiding preparation or test interpretation inside
language models, learned encoders, or a backend-specific physical model.

Decision Model Zero exercises only the backend-neutral 1.x contract from
017.02. It uses exact rational arithmetic over an explicitly declared scalar
state domain. The `topographo` adapter and the OT single-step transport identity
remain 017.04 work.

## Exact demonstration contract

The admitted state domain is:

```text
P = {p in Q | 0 <= p <= 1}
omega_p is represented by the exact rational p
```

Define the unit effect and one ordered binary test explicitly:

```text
u(p)     = 1
e_yes(p) = p
e_no(p)  = 1 - p
T        = (("yes", e_yes), ("no", e_no))
```

For every admitted `p`, not only for the displayed fixtures:

```text
e_yes(p) + e_no(p) = p + (1 - p) = 1 = u(p)
```

The demonstration resolves these two required fixtures in this order:

```text
sharp:     p = 1   -> (("yes", 1),   ("no", 0))
non-sharp: p = 1/3 -> (("yes", 1/3), ("no", 2/3))
```

Both paths must construct the public `Test`, call the public `resolve_test`, and
show the resulting ordered `Distribution`. All state values, effect values,
probabilities, and totals remain `fractions.Fraction` values through resolution.
Decision Model Zero must not use floating-point approximations, nonzero
normalization tolerance, or post-resolution renormalization.

Calling the family a `Test` remains a domain assertion rather than something the
generic constructor proves. The demonstration must therefore state the domain
above and exhibit the complement identity that establishes exhaustiveness on
that domain.

## Installed execution contract

The built distribution must install a console entry point named:

```text
decision-model-zero
```

The README must give this clean-environment path:

```console
python -m pip install decision-model
decision-model-zero
```

A repository-only example script does not satisfy this contract. Validation
must build the wheel, install that wheel into a clean environment, and invoke
the installed entry point without relying on the source checkout or an adjusted
`PYTHONPATH`.

The command writes exactly one JSON document to standard output and writes no
progress, commentary, or environment-dependent data to that stream. A
successful run exits zero. Two runs from the same installed artifact must
produce byte-identical standard output.

## Machine-readable output contract

The output schema identifier is `decision-model-zero/v1`. The document must
contain:

1. `schema`, equal to `decision-model-zero/v1`;
2. `backend`, equal to `generic-exact`;
3. one explicit test description with the admitted state domain and the ordered
   effect descriptors `identity` / `p` and `complement` / `1 - p`;
4. the ordered `sharp` and `non-sharp` cases;
5. for each case, the exact input state, ordered labeled distribution, and exact
   total.

Every exact rational is encoded as a JSON object with integer `numerator` and
`denominator` fields in lowest terms with a positive denominator. JSON decimal
numbers are not an exact-probability encoding. Test callables, Python `repr`
strings, memory addresses, filesystem paths, timestamps, and platform details
must not appear in the output.

The normative shape is:

```json
{
  "schema": "decision-model-zero/v1",
  "backend": "generic-exact",
  "test": {
    "state_domain": "p in Q, 0 <= p <= 1",
    "effects": [
      {"label": "yes", "id": "identity", "expression": "p"},
      {"label": "no", "id": "complement", "expression": "1 - p"}
    ]
  },
  "cases": [
    {
      "id": "sharp",
      "state": {"numerator": 1, "denominator": 1},
      "distribution": [
        {"label": "yes", "probability": {"numerator": 1, "denominator": 1}},
        {"label": "no", "probability": {"numerator": 0, "denominator": 1}}
      ],
      "total": {"numerator": 1, "denominator": 1}
    },
    {
      "id": "non-sharp",
      "state": {"numerator": 1, "denominator": 3},
      "distribution": [
        {"label": "yes", "probability": {"numerator": 1, "denominator": 3}},
        {"label": "no", "probability": {"numerator": 2, "denominator": 3}}
      ],
      "total": {"numerator": 1, "denominator": 1}
    }
  ]
}
```

Whitespace is not semantically significant to consumers, but the implementation
must choose one stable serialization so repeated runs remain byte-identical.
This is a versioned demonstration/presentation schema, not a new serialization
contract for arbitrary `State`, `Effect`, `Test`, or `Distribution` objects.

## Exclusions

Decision Model Zero contains no:

- natural-language input;
- text encoder or language model;
- learned decoder;
- grokking requirement;
- Event enactment;
- sampling or choice policy presented as evaluation;
- `topographo` dependency or OT transport backend;
- claim that the complement test is an arbitrary generalized measurement
  calculus;
- claim that Issue 017 alone supplies a complete generalized OT measurement
  calculus.

The demonstration is `generic-exact`. It must not describe its elementary
complement construction as the OT single-step transport identity, a physical
Born rule, or the future `topographo` integration. That backend is introduced
and bounded separately by 017.04.

## Required artifacts and validation

Produce:

2. the exact generic implementation of the two fixtures above;
3. the versioned machine-readable output above;
4. a short explanation of state, effect, test, distribution, and why this test

5. tests pinning the complete parsed output, rational values, order, labels,

6. a test showing the documented complement identity for the admitted fixture
   states and documentation establishing it algebraically for every admitted
   `p`;
7. a clean-wheel smoke test invoking the installed console entry point twice
   and requiring successful, byte-identical output;
8. a limitations section stating what remains unimplemented and unproved.

The limitations must say at minimum that Decision Model Zero does not provide
state preparation, test interpretation, arbitrary test-admissibility proofs,
backend physics, `topographo` transport, generalized OT measurement,
conditioning, collapse, sampling, decision policy, or intelligent evaluation.

## Done when

A new user can install the built distribution, run `decision-model-zero`, parse
its deterministic JSON, inspect the explicit typed test and both exact results,
and understand the demonstrated complement identity and its scientific boundary
in under five minutes. The wheel-level smoke test and numerical/schema tests
must pass without access to the repository source tree.
