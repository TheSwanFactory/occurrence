# 017.05 — Add preparation and test-interpretation bridges separately

- **Sequence:** 5 of 5
- **Target:** successor SOBER research and implementation programme
- **Depends on:** stable SOBER-0 and backend boundaries
- **Status:** post-launch research sequence
- **Issue effect:** successor work; not an Issue 017 acceptance criterion

## Objective

Extend SOBER beyond already-constituted states and tests without collapsing two distinct representation problems into end-to-end answer imitation.

## Bridge A — preparation

Introduce and evaluate:

```text
Prepare : Datum -> State
```

while holding the effect/test representation fixed and formal.

The acceptance question is not merely whether a learner predicts the final label. It is whether the produced object satisfies the backend’s state contract and preserves the expected resolver behavior across independently supplied admissible tests.

## Bridge B — test interpretation

Only after Bridge A is separately characterized, introduce:

```text
InterpretEffect : TypedPredicate -> Effect
InterpretTest   : TypedQuestion / OutputType -> Test
```

while holding preparation controlled.

The acceptance question is whether the interpreted alternatives form a valid typed test under the backend’s positivity, exhaustiveness, normalization, dimensional, and composition requirements—not merely whether downstream accuracy is high.

## Experimental order

1. fixed formal state and fixed formal test;
2. learned or derived preparation with fixed test;
3. fixed preparation with learned or derived test interpretation;
4. both bridges composed only after each passes independently;
5. downstream sampling, decisions, or Event enactment added only as separately named policy layers.

## Scientific and marketing fence

Do not describe either bridge as solved until its output is validated as the correct semantic object. End-task accuracy alone does not demonstrate state constitution or admissible test realization.

Language models and grokking may be techniques used inside a bridge. They are not SOBER’s native semantics and are not required signatures of success.

## Done when

- each bridge has its own contract, fixtures, metrics, and failure modes;
- state validity and test admissibility are tested independently;
- composed behavior is compared against controlled formal baselines;
- resolver semantics remain unchanged when bridge implementations change;
- claims distinguish demonstrated representation results from broader hypotheses about cognition or intelligence.
