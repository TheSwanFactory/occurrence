## Why the negative looks the way it does

`negative_result_diagnostic.json` is a post-hoc explanatory diagnostic on
already-fixed final states. It adds no scored quantity and reinterprets no
temporal reading.

**The frozen output contract removes most held-out answers from the learned output
support.** With one designated target per seen block, 43 of the 84 Events are ever
a designated answer and **41 are never one**. Full 84-way cross entropy pushes
every non-target logit down, so those 41 receive only downward pressure for the
entire run. Meanwhile 65 of the 96 ROLE_TEST answers and 17 of the 24 NOVEL_TEST
answers are exactly such Events.

The trained models behave accordingly. Over the eight regularized seeds:

```text
ROLE_TEST   65.8% predict a designated target from some other block
            34.2% predict one of the two Events in the query pair
             0.0% predict any never-designated Event
             0.0% correct

NOVEL_TEST 100.0% predict a designated target from some other block
             0.0% correct
```

The model never once emits any of the 41 never-designated Events. Interestingly
this is not the candidate bias doing the work — mean bias is slightly *more*
negative on designated Events (-0.0348) than on never-designated ones (-0.0086) —
so the collapse lives in the candidate embedding geometry.

**But the contract is not the explanation.** The probe faces the identical 48
TRAIN examples and the identical 84-way objective, and on the certified code it
reaches 0.9896 ROLE and 1.0000 NOVEL. The benchmark is solvable under this output
contract. The difference is structural: the probe scores candidates with the *same*
vector it uses to build query features, so structure learned in one role is
automatically available in the other. The frozen main architecture gives each
Event **two independent rows** — an input row used only in query pairs and a
candidate row used only when scored as an answer. Learning "z answers {x,y}"
updates z's candidate row and leaves z's input row untouched. Nothing in the
objective ever pressures an Event's two rows to describe the same object.

So the finite reading available here is that the learner never formed a
role-transferable Event representation at all, rather than forming one the probe
failed to read. This diagnostic does not settle that alternative, and no claim
beyond the tested finite benchmark is made.

## What this establishes

On this exact finite benchmark, with this frozen architecture, regime grid,
horizon and instrument: an opaque-token learner memorizes all designated answers
within 64 updates and shows **no** movement toward role-neutral triad consequence,
no unseen-block extrapolation, and no readable relational organization across
65,536 updates, in either a strongly regularized arm or a matched
zero-weight-decay control, on eight seeds each.

The negative is informative rather than vacuous because the instrument is
independently validated on the same split: the certified code is readable to 0.9896
ROLE / 1.0000 NOVEL by the same fresh decoder, and the matched non-automorphic
scramble is not.

## What this does not establish

```text
that all grokking is algebra discovery
that low dimensionality is necessary
that our SFP coordinates would have appeared neuron-by-neuron
that OT is superior to transformers or language models
H_native, or anything about Outcome constitution
open-ended or language-scale representation discovery
physical Event or Outcome semantics
that probe decodability by itself would prove causal use
that NOVEL_TEST success was ever guaranteed by the training examples
that no architecture can grok this benchmark
```

The last line is the one worth emphasizing. A single frozen architecture failing to
grok a benchmark is evidence about that architecture under that output contract,
not about the benchmark's difficulty or about grokking in general. The untied
input/candidate tables are a specific, identified candidate cause, and testing a
tied-table variant would be a new preregistered experiment, not a repair of this
one.
