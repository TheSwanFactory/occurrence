## Scientific question

The accepted `014.03a` negative used two independent Event tables:

```text
input Event embedding      84 x 64
candidate Event embedding  84 x 64
```

and observed fast answer memorization with no role consequence, no unseen-block extrapolation, and no readable relation in any of 16 runs.

This successor changes exactly the conceptual seam identified by that result:

```text
ONE shared Event embedding E[0..83] in R^64

Event x as a query input     -> E[x]
Event x as a candidate answer -> the SAME E[x]
```

The experiment asks whether forcing an Event to remain the same learned object across question and answer roles is sufficient to alter the memorization-to-consequence trajectory.

Do **not** assume tying will cause grokking. A second clean M4 is a valid and important result.

## 2. Tied architecture — the only conceptual model change

Use one shared trainable Event table:

```text
E : 84 x 64
candidate bias : 84

for unordered query pair a,b:
    p = concat(E[a] + E[b], E[a] * E[b], abs(E[a] - E[b]))   # 192
    q = Linear(192,256) -> GELU -> Linear(256,64)

for every candidate c:
    score(c|a,b) = dot(q, E[c]) / sqrt(64) + bias_c

loss = full 84-way cross entropy on the designated TRAIN target
```

There must be **no second Event table and no role-specific Event projection**. The exact same row `E[x]` must be consumed whenever Event `x` appears as either query input or candidate answer.

Keep unchanged from `014.03a`:

```text
embedding width 64
pair feature form
MLP widths and GELU
candidate bias
full 84-way objective
full-batch training
initialization family
opaque token vocabulary
no augmentation
input-swap invariance
```

Initialization:

```text
E and Linear weights: Xavier uniform, gain 1.0
all biases: zero
```

Before training, mechanically verify that the model has exactly one Event embedding parameter tensor and that candidate scoring references that tensor object, not a copy.

A fallback candidate is capacity-qualified if all 4 calibration seeds reach exact TRAIN accuracy `1.0` by update 8192.

Selection key among qualified candidates:

1. nonzero weight decay preferred over zero;
2. weight decay descending;
3. median first exact-fit update ascending;
4. learning rate ascending.

Write the result as `capacity_fallback_selection.json` before any scored held-out evaluation.

Rules:

- Always run both primary matched arms.
- If at least 7/8 scored seeds in either primary arm reach exact TRAIN fit by update 8192, **do not run a fallback scored arm**; the primary architecture test is capacity-qualified.
- If neither primary arm reaches that 7/8 criterion, and a fallback candidate qualified on calibration, run one additional `CAPACITY-FALLBACK` scored arm on the eight scored seeds.
- If neither primary arm capacity-qualifies and no fallback candidate qualifies, report `NO-TIED-CAPACITY` as an informative optimization/capacity boundary. Do not call it an M4 grokking result.

This fallback exists only to prevent failure-to-fit from masquerading as failure-to-grok. It is not part of the matched single-variable comparison unless invoked.

## 10. Comparison logic

The primary mechanistic contrast is:

```text
014.03a untied identity:
    Event_input[x] and Event_candidate[x] independent
    accepted outcome: uniform M4

014.05 tied identity:
    one shared E[x] across both roles
    outcome: to be measured
```

Keep these conclusions separate:

```text
T0  tied model cannot reliably fit TRAIN
    -> no conclusion about grokking; report capacity/optimization boundary

T1  tied model fits TRAIN but remains M4
    -> role identity tying alone is insufficient under this benchmark/training signal

T2  tied model gains ROLE_TEST but not NOVEL_TEST
    -> role-neutral seen-triad consequence emerges without stronger unseen-block algebra

T3  tied model gains ROLE_TEST and readable representation, with t_repr near/before t_gen
    -> evidence that role-neutral shared Event representation accompanies consequence generalization

T4  tied model also gains NOVEL_TEST / t_repr_global or exact full relation
    -> stronger finite evidence of relation-level organization beyond seen-triad role transfer
```

Do not claim tying is *necessary* from a positive result; this experiment tests sufficiency relative to one untied predecessor. Do not claim all grokking works this way.
