# 007.05 — Klein conjecture: fair grokking separates stipulated interface from learned relation

- **Date:** 2026-09-08
- **Author:** Klein
- **Status:** conjecture / reframing note
- **Issue:** 007 — TLM result interface
- **Motivation:** reconsideration of what the conventional modular-arithmetic grokking benchmark actually asks a model to learn

## 1. Conjecture

The apparent TLM result-interface obstruction in GPT 007 may be partly an artifact of imposing a stronger requirement on TLM than on the conventional grokking baseline.

A fair modular-arithmetic grokking comparison should distinguish three layers:

```text
externally stipulated encoding
    -> learned relational/computational dynamics
    -> externally stipulated decoding/readout.
```

The conventional baseline is not normally required to derive the semantic identity of its input tokens, modulus, or output coordinates from its internal dynamics. Those meanings are supplied by the experimental configuration and training data.

Therefore a TLM need not derive an OT-native p-way Outcome/effect vocabulary as a prerequisite for the ordinary claim that it **groks modular arithmetic**.

The conjecture is:

> **If conventional and TLM models are supplied comparably stipulated input and output semantics, then modular grokking should be judged by held-out generalization of the learned middle relation, not by whether TLM independently constitutes the benchmark's externally defined symbol vocabulary or probability head.**

## 2. What the conventional benchmark actually supplies

For fixed prime/modulus `p`, the usual modular-addition experiment is more accurately written

```text
M_p(a,b) -> c,
```

with

```text
c = a+b mod p.
```

The experimenter already supplies at least:

1. a token/index set interpreted as residues `0,...,p-1`;
2. the presentation of `a` and `b` to the model;
3. the fixed experimental modulus `p` (often as model/dataset context rather than a query token);
4. an output/readout coordinate system interpreted as the same residue labels;
5. a loss comparing the declared target coordinate `c` with the model readout.

Thus neither the input representation nor the result-label semantics is normally an independently discovered mathematical object.

For a finite-logit softmax model, “groks mod p” does not require literal probability one on the correct coordinate. The operational criterion is near-perfect held-out generalization, typically

```text
argmax_j P(j | a,b) = a+b mod p
```

on unseen pairs after the characteristic delayed-generalization/grokking regime.

## 3. Hidden asymmetry in the current TLM test

GPT 006–007 have deliberately demanded a stronger OT-native bridge:

```text
constituted TLM result
    -> certified OT effect
    -> formal test / probability-facing readout.
```

That is scientifically valuable, but it is not obviously part of the conventional grokking claim.

If the baseline receives externally stipulated residue encodings and a p-way decoded output vocabulary, while TLM is required additionally to derive:

```text
- what its input participants mean;
- what counts as a result symbol;
- a p-way result family;
- the result-to-effect map;
- the probability-facing test;
```

then a failure of the latter does not by itself show that the TLM failed to learn modular arithmetic. It may show only that the TLM failed the **stronger native-interface constitution problem**.

## 4. Proposed fair benchmark statement

For each fixed `p`, supply explicit experimenter-defined maps/interfaces sufficient to present residues to each architecture and decode its declared benchmark result.

Abstractly, permit

```text
ε_p : Z_p -> X_p
δ_p : Y_p -> Z_p
```

where `ε_p` is the stipulated input encoding and `δ_p` is the stipulated benchmark decoder/readout appropriate to the architecture.

Then ask whether training produces a learned map/dynamics `T_p` such that on held-out pairs

```text
δ_p(T_p(ε_p(a), ε_p(b))) = a+b mod p.
```

The encoding and decoder must be fixed independently of the held-out answers and must not themselves implement modular addition.

Architecture-specific internal representations are allowed; semantic privilege is not. The comparison should equalize what is externally stipulated, not force identical internal state types.

## 5. Stronger triadic version

Because TLM is explicitly triadic, the more diagnostic relation is

```text
a+b-c = 0 mod p.
```

A stronger fair probe asks whether one learned relational structure supports all three completions:

```text
(a,b,?) -> c
(a,?,c) -> b
(?,b,c) -> a
```

under comparably stipulated encodings/decodings, including held-out triples or role permutations not used for direct supervision where the protocol permits.

Success would support the claim that TLM learned/realized the ternary modular relation rather than merely one privileged directed lookup.

This remains distinct from proving that its internal geometry is canonically isomorphic to `Z_p` without an external interpretation.

## 6. Three claims that must remain separate

### H_weak — ordinary grokking

```text
With stipulated benchmark encoding and decoding,
TLM generalizes modular addition on held-out inputs.
```

### H_rel — role-neutral relational grokking

```text
One learned TLM relation supports correct completion in all three modular roles.
```

### H_native — OT-native interface constitution

```text
The TLM/OT architecture itself canonically constitutes a result/effect/test
structure that can be interpreted as the modular result vocabulary without
an externally stipulated benchmark decoder.
```

GPT 006–007 and Outcome 016 materially constrain `H_native`.

Failure of `H_native` does **not** logically falsify `H_weak` or `H_rel`.

Conversely, success on `H_weak` does not establish `H_native`.

## 7. Relation to Outcome 016

Outcome 016 independently shows that the 15 singleton Fixed classes are not a hard cardinality limit on configured result effects: a legal horizon-two resource partition supports at least 1100 pairwise distinct effects.

That result further weakens any inference from the 15-class singleton quotient to an intrinsic inability to represent a p-way benchmark result vocabulary.

But the present conjecture is logically prior to that capacity result: even if OT-native effect constitution were difficult, a fair conventional grokking comparison need not require the architecture to derive the benchmark decoder at all.

## 8. Falsification / next task

This conjecture should be tested by rewriting the GPT-005/007 modular experiment as a strict apples-to-apples interface audit.

The follow-on should identify exactly what semantic/interface information is externally supplied to the baseline and to TLM, then run at least:

```text
A. weak fixed-p modular generalization with matched stipulated interfaces;
B. TLM role-neutral triadic completion;
C. the stronger OT-native effect/test readout as a separate experiment, not a prerequisite for A or B.
```

A decoder that contains a lookup table for held-out answers, computes modular arithmetic itself, or is fitted using held-out targets invalidates the comparison.

## 9. Consequence if confirmed

If confirmed, GPT 007 should be reframed.

The 15-class and configured-effect investigations remain important for the stronger question of an **OT-native probability-facing result interface**, but they cease to be blockers on the ordinary empirical question:

```text
Does TLM grok modular arithmetic under the same level of externally supplied semantic interface as the baseline?
```

The benchmark would then test the learned relational/computational middle, while native Outcome/effect constitution remains a separate and stronger research programme.
